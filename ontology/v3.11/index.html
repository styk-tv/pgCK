Concept Kernel Protocol v3.11 docs

CKP Core Ontology v3.11 in progress

The operating definition of a concept kernel: what one is, what it does, and what the substrate refuses on its behalf. The root is self-contained — every ckp: term it references, it declares — and it is authored under three rules: every constraint uses a component the gating engine is measured to enforce; no class IRI is the subject of a domain-carrying predicate; and every constraint reads only the candidate body plus its stamped parent closure. What cannot be enforced at the gate is declared as a gap, with a reason.

The declared gap

G-1 — cross-node kind integrity. Body locality places one property beyond the instance gate: that a referenced IRI is of the kind the reference intends (a kernel bearing one organ of each kind, a grant targeting an organ, a membership holding a role). The root states the ranges so the check is expressible as a store-level query over sealed rows, and declares the gap rather than carrying a constraint that would read as enforcement while refusing valid writes.
